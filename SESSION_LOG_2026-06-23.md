## What the project is
A MuJoCo re-implementation of **Cheney et al. 2013 "Unshackling Evolution"**: evolve
voxel-based soft robots whose 3-D bodies are generated by a **CPPN+NEAT** genome,
simulate under gravity, select for locomotion. Pipeline: `CPPNGenome` → voxel grid (4
materials: phase-0° muscle, phase-180° muscle, soft passive, stiff passive) → MuJoCo
spatial-tendon physics (`MuJoCoTendonPhysics`) → fitness → selection.

## Ruled out / learned
- **GPU/MJX is the wrong tool here:** WSL2 + `jax[cuda12]` on the A4500 benchmarked
  **~140× slower than one CPU thread** and **OOMs on real-size (300-body) robots** (batched
  dense constraint solver wants TiB); ~123 s recompile per morphology. CPU (≈100k steps/s/core
  × 30 cores) is right. Autotune flag was NOT the cause (verified). Benchmarks: `fair_mjx_bench.py`,
  `batch_scale_test.py`, `thorough_mjx_bench.py`. (WSL `mjx` conda env exists if ever needed.)
- **Modern Standby** silently kills long unattended runs (no traceback). Check Kernel-Power
  506/507 before assuming a code bug.

## Glossary
- **Body-encoder problem (the actual issue):** the limiter is the CPPN that *generates the body*.
  It was stuck painting simple uniform single-material blobs (0 hidden nodes), which can only
  pulse in unison → no good gait possible regardless of control. Fix = speciation + A2 + elitism
  so the encoder complexifies and expresses differentiated, multi-material bodies.
- **Controller problem (NOT the issue here):** the limiter is the *brain* driving the muscles.
  Original hypothesis was the CPG getting reset to random on every body change (fragile
  co-adaptation) → A1 removed it, which did NOT break the plateau → controller wasn't the bottleneck.

## B5 scope (MuJoCo flex/deformable reformulation) — start fresh next session
**What:** replace the current physics — each voxel = a free rigid body (6 DOF) joined by
spatial-tendon springs (≈1800 DOF/robot + many constraints, superlinear solver cost) — with
MuJoCo's **native deformable bodies** (`flex`/`flexcomp`): a soft-body lattice simulated as one
conditioned object. Goal: far **faster + more stable + more realistic**. This is THE speed lever
(GPU ruled out), and run speed caps everything.
**Biggest unknown / first step = a FEASIBILITY SPIKE:** can a MuJoCo flex voxel-robot be
*actuated as muscle* (volumetric contraction) and locomote, and is it actually faster than the
tendon model? MuJoCo flex is newish; actuating a deformable body is the crux. Build a small
actuated flex robot, confirm it contracts + moves + beats the tendon model on speed, THEN commit.
**Design decisions to settle with user:** (1) parallel flex-physics mode behind a flag (keep the
working tendon model) vs full replacement — lean parallel/flag; (2) how to map the 4 materials
(2 muscle phases via actuated rest-length/element modulation; soft/stiff via edge stiffness);
(3) accept that flex results are a NEW baseline, not comparable to the tendon-model history.
**Then C6 (HyperNEAT):** CPPN outputs per-voxel phase/frequency so the GAIT itself evolves
(currently there is NO brain — just fixed material-phase sine actuation; see Q2 below).
